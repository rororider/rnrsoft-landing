## 1. 한 줄 요약

**1인 앱 개발 스튜디오 "rnrsoft"의 공식 홈페이지.** 받아쓰기 노트를 시작으로 생산성·학습 앱을 만드는 개발자의 얼굴이 되는 랜딩. Google Play 개발자 페이지로 등록되며, 방문자(사용자·구글 심사자·잠재 협업자)에게 "이 개발자는 믿을 만하고 감각 있다"는 인상을 줘야 한다. 정적 페이지(HTML/CSS), 다크모드 기반.

---

## 2. 이 사이트가 해야 할 일 (디자인 우선순위 = 이 순서)

1. **첫인상으로 "실력 있는 개발자"라는 신뢰를 준다** → 히어로가 가장 중요. 진부한 템플릿 느낌 금지. 유니크한 비주얼 후크(모션/타이포/그래픽) 하나는 있어야 함.
2. **앱을 매력적으로 진열한다** → 현재 1개(받아쓰기 노트), 앞으로 3~5개로 늘어남. 카드가 늘어나도 안 무너지는 갤러리 구조.
3. **개발자를 소개한다** → 무엇을·왜 만드는지, 철학. 짧지만 개성 있게.
4. **연락·법적 페이지로 안내한다** → 문의 이메일, 개인정보처리방침·이용약관 링크(구글 심사 필수).

---

## 3. 디자인 톤 — **디자인팀이 2~3방향 제안**

지금은 "다크(#0e1117) + 레드/옐로 그라디언트 포인트"의 무난한 톤이다. 이걸 다듬든 갈아엎든, **아래 방향 중 2~3개를 제안**해 주면 좋겠다. 공통 요건: **다크모드 기반, 개발자스러운 감각, 진부하지 않게.**

제안 후보 방향(참고용, 이대로일 필요 없음):
- **(A) 터미널/코드 감성**: 모노스페이스 악센트, 커맨드라인 모티프, 미세한 글리치/타이핑 애니메이션. "개발자가 만든 티" 확실.
- **(B) 미니멀 프리미엄**: Linear·Vercel·Raycast 계열. 절제된 여백, 고급 그라디언트, 은은한 글로우, 부드러운 마이크로 인터랙션.
- **(C) 크리에이티브 볼드**: 큰 타이포그래피, 대담한 컬러 블록, 비대칭 레이아웃. 스튜디오의 개성 강조.

요건:
- **다크모드 필수** (라이트 토글은 선택)
- 한글 가독성 좋은 타이포 (Pretendard/Noto Sans KR 등 + 영문 악센트 폰트 조합 환영)
- 앱이 늘어나도 유지되는 카드/그리드 시스템
- 과하지 않은 모션 — 스크롤 리빌, hover 미세 반응 정도 (무거운 라이브러리 없이 CSS/미니멀 JS로)
- "1인 스튜디오"의 진정성 (대기업 흉내 X, 개인 개발자의 감각 O)

## 5. 화면 인벤토리 (단일 페이지 랜딩 + 하위 2페이지)

### 메인 랜딩 (index) — 세로 스크롤 원페이지
- **A. 헤더/내브**: 브랜드 로고 + 앵커 링크(앱/소개/문의). sticky, 스크롤 시 배경 블러.
- **B. 히어로**: 강력한 헤드라인 + 서브카피 + CTA("앱 둘러보기"). **여기에 유니크한 비주얼 후크.**
- **C. 앱 갤러리**: 앱 카드들. 각 카드 = 아이콘/이름/상태배지(서비스중·준비중)/설명/기능 태그/링크. 현재 항목:
  - **받아쓰기 노트** (서비스 중): 말하면 자동으로 받아적히는 음성 메모·학습 노트. AI 정리·질문·학습카드. 4개 언어. → https://note.rnrsoft.vip
  - **준비 중 슬롯** 1개 (곧 새 앱)
- **D. 개발자 소개(About)**: 무엇을 만드는지 / 개인정보 존중 / 기술(웹·PWA·AI) / 플랫폼(웹·모바일·Google Play). 4블록 정도.
- **E. 문의(Contact)**: 이메일 CTA.
- **F. 푸터**: 저작권 + 개인정보처리방침/이용약관/문의 링크.

### 하위 페이지 (톤 일관되게, 읽기 좋은 문서형)
- **privacy.html** — 개인정보처리방침 (내용 이미 있음, 디자인만 통일)
- **terms.html** — 이용약관 (내용 이미 있음, 디자인만 통일)

## 6. 이번에 꼭 살릴 포인트 (Top 5)

1. **히어로의 유니크함**: 남들 다 쓰는 "그라디언트 + 큰 글자 + 버튼" 조합을 넘어서는 후크 하나. (예: 받아쓰기 컨셉을 살린 타이핑/음성 웨이브 모티프, 코드 라인 애니메이션 등)
2. **앱 카드의 완성도**: 앱이 주인공. 카드가 "앱스토어 진열대"처럼 탐나 보이게. 상태 배지·스크린샷/목업 자리 고려.
3. **개발자 개성**: 1인 스튜디오의 진정성. About을 형식적으로 X, 개발자 목소리가 느껴지게.
4. **일관된 시스템**: 컬러·타이포·간격·컴포넌트가 3페이지(홈/약관/개인정보)에서 통일.
5. **가벼움**: 정적 페이지 + Cloudflare Pages 배포. 무거운 프레임워크·큰 이미지 남발 금지. 빠르게 뜨는 사이트.

## 7. 금지/주의 사항

- **콘텐츠(문구/링크/법적 페이지)는 유지·개선만** — 앱 정보·연락처·개인정보/약관 링크는 반드시 남을 것.
- 다크모드에서 텍스트·버튼 대비 확보(가독성).
- 이모지 로고는 **정식 SVG 로고로 대체 제안** 환영.
- 스크린샷/목업이 필요하면 **플레이스홀더 자리**로 표시 (실제 앱 스크린샷은 우리가 나중에 삽입).
- 과한 애니메이션으로 성능 저하 X — 저사양 모바일에서도 부드럽게.
- 개발자스러움 ≠ 촌스러움. "감각 있는 개발자"가 목표.

---

## 8. 해상도 / Fidelity

- **데스크탑**: 1440px 기준 + 1024px 반응형.
- **모바일**: 390px(iPhone) 기준. 내브 축소·카드 1열.
- **Fidelity**: 고충실(hi-fi) 시안 — 색·타이포·간격·모션 명세까지. 특히 **① 히어로**, **② 앱 갤러리 섹션** 2개는 데스크탑+모바일 둘 다 그려주면 좋겠다.
- **결과물 형식**: standalone HTML/CSS(+ 최소 JS) 선호 — 우리가 Cloudflare Pages에 바로 포팅. React+Tailwind 컴포넌트도 OK. 로고·심볼은 SVG로.
